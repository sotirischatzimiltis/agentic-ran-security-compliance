### **Violations Found**

#### **1. Ciphering Algorithms**
- **Field**: `ciphering_algorithms = ( "nea0" );`
- **Violation**:
  - **`nea0` (Null ciphering) is explicitly prohibited for user data and RRC-signalling in 3GPP TS 33.501 and O-RAN.WG4 security requirements** unless regulations explicitly forbid ciphering.
  - **Security Risk**: Using `nea0` disables confidentiality protection, exposing user data and signalling to eavesdropping and tampering.
- **Specification Reference**:
  - 3GPP TS 33.501 V17.6.0, Section 5.3.2: *"Confidentiality protection should be used whenever regulations permit."*
  - O-RAN.WG4: *"The gNB shall support ciphering of user data and RRC-signalling."*

#### **2. Integrity Algorithms**
- **Field**: `integrity_algorithms = ( "nia2", "nia0" );`
- **Violation**:
  - **`nia0` (Null integrity) is explicitly prohibited for signalling and user data in 3GPP TS 33.501** unless regulations explicitly forbid integrity protection.
  - **Security Risk**: Using `nia0` disables integrity protection, exposing signalling and user data to tampering and replay attacks.
- **Specification Reference**:
  - 3GPP TS 33.501 V17.6.0, Section 5.11.1.2: *"Integrity protection is mandatory for all signalling and user data."*

#### **3. DRB Integrity**
- **Field**: `drb_integrity = "no";`
- **Violation**:
  - **DRB integrity protection is mandatory for all DRBs** if the User Plane Security Enforcement policy requires it (3GPP TS 33.501).
  - **Security Risk**: Disabling DRB integrity exposes user plane data to tampering and injection attacks.
- **Specification Reference**:
  - 3GPP TS 33.501 V17.6.0, Section 5.11.1: *"All DRBs belonging to a PDU session for which the User Plane Security Enforcement information indicates that UP integrity protection is required shall be configured with integrity protection."*

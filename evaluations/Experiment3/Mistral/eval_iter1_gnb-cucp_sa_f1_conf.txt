### **Violations Found**

#### **1. Ciphering Algorithm (`nea0`)**
- **Current Value**: `("nea0")`
- **Specification Reference**:
  - **3GPP TS 33.501 V17.6.0 (2023-12)** explicitly states that **`nea0` (NULL ciphering) is prohibited for use in 5G except for unauthenticated IMS emergency sessions**.
  - **O-RAN.WG4.Security Requirements** mandate that **confidentiality protection should be used whenever regulations permit**.
- **Security Risk**:
  - **`nea0` provides no encryption**, leaving RRC and user data exposed to eavesdropping, tampering, and replay attacks.
  - Violates **3GPP and O-RAN security best practices** for confidentiality protection.
- **Fix Required**:
  - Replace `nea0` with a **strong ciphering algorithm** (`nea1`, `nea2`, or `nea3`).

#### **2. Integrity Algorithm (`nia0`)**
- **Current Value**: `("nia2", "nia0")`
- **Specification Reference**:
  - **3GPP TS 33.501 V17.6.0 (2023-12)** prohibits the use of **`nia0` (NULL integrity) for 5G NAS and AS security contexts**.
  - **Exception**: Only allowed for **unauthenticated IMS emergency sessions**.
- **Security Risk**:
  - **`nia0` provides no integrity protection**, allowing attackers to **modify, inject, or replay** RRC and user data without detection.
  - Violates **3GPP and O-RAN integrity requirements**.
- **Fix Required**:
  - Remove `nia0` from the list of preferred integrity algorithms.

#### **3. DRB Integrity (`drb_integrity = "no"`)**
- **Current Value**: `"no"`
- **Specification Reference**:
  - **3GPP TS 33.501 V17.6.0 (2023-12)** mandates that **DRB integrity protection must be enabled** if the **SMF enforces UP integrity protection**.
  - **O-RAN.WG4.Security Requirements** align with 3GPP, requiring **integrity protection for DRBs** unless explicitly exempted.
- **Security Risk**:
  - **Disabling DRB integrity** allows attackers to **modify, inject, or replay** user plane data without detection.
  - Violates **3GPP and O-RAN security requirements** for user plane protection.
- **Fix Required**:
  - Set `drb_integrity = "yes"`.

#### **4. F1-C Port Numbers (`local_s_portc = 501`, `remote_s_portc = 500`)**
- **Current Value**:
  - `local_s_portc = 501`
  - `remote_s_portc = 500`

  - **O-RAN.WG4** aligns with 3GPP for **F1-C port requirements**.
- **Security Risk**:
  - Using **non-standard ports** may expose the interface to **unauthorized access, scanning, or attacks**.
  - Violates **3GPP and O-RAN port assignment requirements**.
- **Fix Required**:

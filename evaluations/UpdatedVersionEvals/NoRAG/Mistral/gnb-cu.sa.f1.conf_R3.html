Security Compliance Report

File: gnb-cu.sa.f1.conf
Function: CU
Status: Non-Compliant
Compliance Assessment Summary

The configuration file for the gNB-CU contains explicit violations of 3GPP security requirements for integrity and confidentiality protection. Specifically, the use of 'nea0' (null ciphering) and 'nia0' (null integrity) algorithms, along with the explicit disabling of DRB integrity protection, violates the SMF policies requiring integrity and confidentiality protection.

Violation Details
1. Use of Null Ciphering Algorithm (nea0) in Preferred List
Critical

Non-Compliant Value: ( "nea0" )

Fix: Remove 'nea0' from the list of preferred ciphering algorithms and replace it with valid algorithms such as 'nea2', 'nea1', or 'nea3'.

Reference: TS 33.501, clause 6.7.2, TS 33.501, clause 5.3.2

Specification Text:

3GPP TS 33.501, clause 6.7.2, prohibits the use of null ciphering (nea0) for DRBs. SMF Confidentiality Policy is set to 'Required', making the use of nea0 non-compliant.

2. Use of Null Integrity Algorithm (nia0) in Preferred List
Critical

Non-Compliant Value: ( "nia2", "nia0" )

Fix: Remove 'nia0' from the list of preferred integrity algorithms and replace it with valid algorithms such as 'nia2', 'nia1', or 'nia3'.

Reference: TS 33.501, clause 6.7.2, TS 33.501, clause 5.3.2

Specification Text:

3GPP TS 33.501, clause 6.7.2, prohibits the use of null integrity (nia0) for DRBs. SMF Integrity Policy is set to 'Required', making the inclusion of nia0 non-compliant.

3. DRB Integrity Protection Explicitly Disabled
Critical

Non-Compliant Value: "no"

Fix: Set 'drb_integrity' to "yes" to enable integrity protection for DRBs.

Reference: TS 33.501, clause 5.3.2

Specification Text:

3GPP TS 33.501, clause 5.3.2, mandates integrity protection for all DRBs. SMF Integrity Policy is set to 'Required', making the explicit disabling of DRB integrity non-compliant.

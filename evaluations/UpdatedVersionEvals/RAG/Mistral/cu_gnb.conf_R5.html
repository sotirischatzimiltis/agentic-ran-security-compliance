Security Compliance Report

File: cu_gnb.conf
Function: CU
Status: Non-Compliant
Compliance Assessment Summary

The CU configuration file violates 3GPP and O-RAN security requirements for ciphering and integrity protection of Data Radio Bearers (DRBs). Specifically, the use of 'nea0' (null ciphering) and 'nia0' (null integrity) is explicitly prohibited by 3GPP when SMF Integrity and Confidentiality Policies are marked as 'Required'. Additionally, the `drb_integrity` parameter is set to 'no', which violates the SMF Integrity Policy.

Violation Details
1. Use of Null Ciphering Algorithm (nea0) for DRBs
Critical

Non-Compliant Value: ( "nea0" )

Fix: Replace 'nea0' with a non-null ciphering algorithm such as 'nea2' or 'nea1'.

Reference: 3GPP TS 33.501, clause 5.10.2, 3GPP TS 33.523, clause 5.2.2.1.4

Specification Text:

3GPP TS 33.501 explicitly prohibits the use of null ciphering algorithms (nea0) for Data Radio Bearers (DRBs) when confidentiality is required by the SMF policy.

2. Use of Null Integrity Algorithm (nia0) for DRBs
Critical

Non-Compliant Value: ( "nia2", "nia0" )

Fix: Remove 'nia0' from the list of integrity algorithms.

Reference: 3GPP TS 33.501, clause 5.11.1.2, 3GPP TS 33.501, Annex D

Specification Text:

3GPP TS 33.501 explicitly prohibits the use of null integrity algorithms (nia0) for Data Radio Bearers (DRBs).

3. DRB Integrity Protection Disabled
Critical

Non-Compliant Value: "no"

Fix: Set `drb_integrity` to "yes".

Reference: 3GPP TS 33.501, clause 5.3.2, 3GPP TS 33.523, clause 5.2.2.1.5, O-RAN.WG11.TS.STS-R004-v11.00, clause 4.2.2.1.11

Specification Text:

3GPP TS 33.501 and TS 33.523 mandate that integrity protection must be enabled for DRBs when the SMF Integrity Policy is marked as 'Required'.

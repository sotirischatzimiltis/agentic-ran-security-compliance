Security Compliance Report

File: gnb-cucp.sa.f1.conf
Function: CU-CP
Status: Non-Compliant
Compliance Assessment Summary

The CU-CP configuration file contains explicit violations of 3GPP security requirements for ciphering and integrity algorithms. Specifically, the use of 'nea0' (null ciphering) and 'nia0' (null integrity) in the preferred algorithms list, and the explicit disabling of DRB integrity protection ('drb_integrity = no'), are critical security risks.

Violation Details
1. Use of Null Ciphering Algorithm (nea0) in Preferred Algorithms List
Critical

Non-Compliant Value: ( "nea0" )

Fix: Remove 'nea0' from the list of preferred ciphering algorithms and replace it with secure algorithms such as 'nea2' and 'nea1'.

Reference: 3GPP TS 33.501 clause 5.3.2, 3GPP TS 33.501 clause 5.2.2

Specification Text:

3GPP TS 33.501 clause 5.3.2 states that confidentiality protection should be used whenever regulations permit. The use of 'nea0' (null ciphering) is explicitly discouraged unless required by regional regulations.

2. Use of Null Integrity Algorithm (nia0) in Preferred Algorithms List
Critical

Non-Compliant Value: ( "nia2", "nia0" )

Fix: Remove 'nia0' from the list of preferred integrity algorithms and ensure only secure algorithms such as 'nia2' and 'nia1' are used.

Reference: 3GPP TS 33.501 clause 5.11.1.2

Specification Text:

3GPP TS 33.501 clause 5.11.1.2 defines 'nia0' as the null integrity protection algorithm. Its use is explicitly discouraged unless required by regional regulations, as it provides no integrity protection.

3. Explicit Disabling of DRB Integrity Protection
Critical

Non-Compliant Value: "no"

Fix: Set 'drb_integrity' to 'yes' to enable integrity protection for DRBs.

Reference: 3GPP TS 33.501 clause 6.6.2, 3GPP TS 38.300 clause 13.1

Specification Text:

3GPP TS 33.501 clause 6.6.2 and TS 38.300 clause 13.1 state that integrity protection for DRBs is mandatory for UEs connected to 5GC. Explicitly disabling DRB integrity protection violates this requirement.

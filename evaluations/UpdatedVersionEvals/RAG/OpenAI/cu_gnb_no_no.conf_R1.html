Security Compliance Report

File: cu_gnb_no_no.conf
Function: CU
Status: Non-Compliant
Compliance Assessment Summary

The configuration is non-compliant because both drb_ciphering and drb_integrity are set to "no" while the SMF Integrity Policy and SMF Confidentiality Policy are both 'Required'. 3GPP TS 33.501 and related specifications require that when the security policy sent by SMF requires integrity and confidentiality, ciphering and integrity protection shall be activated for DRBs. Disabling these protections explicitly violates this requirement and constitutes a critical security vulnerability.

Violation Details
1. DRB ciphering is disabled while SMF Confidentiality Policy is Required
Critical

Non-Compliant Value: no

Fix: Set drb_ciphering = "yes";

Reference: 3GPP TS 33.523 5.2.2.1.4, 3GPP TS 33.501 5.3.2, 3GPP TS 38.300 13.1

Specification Text:

CU must enforce ciphering for DRBs when the SMF Confidentiality Policy is Required. 3GPP mandates user data confidentiality on the DRB if so configured by SMF.

2. DRB integrity is disabled while SMF Integrity Policy is Required
Critical

Non-Compliant Value: no

Fix: Set drb_integrity = "yes";

Reference: 3GPP TS 33.523 5.2.2.1.4, 3GPP TS 33.501 5.3.2, 3GPP TS 38.300 13.1

Specification Text:

CU must enforce integrity protection for DRBs when the SMF Integrity Policy is Required. 3GPP mandates user data integrity on the DRB if so configured by SMF.

Reflection Agent Analysis
REVISION NEEDED: NO

The original config explicitly contains the insecure settings drb_ciphering = "no" and drb_integrity = "no" which violate the policies requiring these to be enabled. The violations have valid evidence excerpts from the original config and their kb_evidence_ids are present and consistent with 3GPP requirements. The corrected config properly fixes the violations by setting drb_ciphering = "yes" and drb_integrity = "yes", changing only the necessary lines, and maintaining all other configurations untouched. No other insecure settings are found in either original or corrected configs. Thus, the corrected configuration is compliant and no further revision is needed.

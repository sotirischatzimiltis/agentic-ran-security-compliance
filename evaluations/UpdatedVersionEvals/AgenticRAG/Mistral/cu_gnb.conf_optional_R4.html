Security Compliance Report

File: CU_Config_File.cfg
Function: CU
Status: Non-Compliant
Compliance Assessment Summary

The CU configuration file violates 3GPP and O-RAN security requirements for ciphering and integrity protection algorithms. Specifically, the use of 'nea0' (null ciphering) and 'nia0' (null integrity) algorithms is explicitly prohibited by 3GPP unless under specific conditions that are not met in this configuration. Additionally, while DRB integrity protection is disabled, this is permissible under the given SMF Integrity Policy (Optional).

Violation Details
1. Use of Null Ciphering Algorithm (nea0)
Critical

Non-Compliant Value: "nea0"

Fix: Remove "nea0" from the list of ciphering algorithms and replace it with approved algorithms such as "nea2" or "nea1".

Reference: 33.501 clause 5.2.2, 33.511 clause 4.2.2.1.6

Specification Text:

3GPP TS 33.501 clause 5.2.2 mandates that NEA0 (null ciphering) shall not be used unless for specific cases like unauthenticated emergency calls. The use of NEA0 in this configuration is explicitly non-compliant.

2. Use of Null Integrity Algorithm (nia0)
Critical

Non-Compliant Value: "nia0"

Fix: Remove "nia0" from the list of integrity algorithms and replace it with approved algorithms such as "nia2" or "nia1".

Reference: 33.501 clause 5.2.2

Specification Text:

3GPP TS 33.501 clause 5.2.2 mandates that integrity protection algorithms different from NIA0 must be used for RRC signaling, except for unauthenticated emergency calls. The inclusion of NIA0 in this configuration is explicitly non-compliant.

3. DRB Integrity Protection Disabled
Medium

Non-Compliant Value: "no"

Fix: Enable DRB integrity protection by setting 'drb_integrity = "yes"' if the SMF Integrity Policy permits or requires it.

Reference: 33.501 clause 5.2.2, 38.300 clause 12.2

Specification Text:

While 3GPP TS 33.501 clause 5.2.2 and TS 38.300 clause 12.2 permit DRB integrity protection to be optional, its deactivation should align with explicit SMF policies. Given the SMF Integrity Policy is marked as 'Optional,' this configuration is compliant but not recommended for security best practices.

File: gnb-cucp.sa.f1.conf
Function: CU-CP
Status: Non-Compliant
Compliance Assessment Summary

The configuration explicitly disables integrity protection for DRBs (drb_integrity = "no"), which may result in a lack of user data integrity protection. While integrity and ciphering for DRBs are optional unless required by policy, explicitly setting drb_integrity to 'no' means PDCP PDU user plane traffic is not integrity protected. This is allowed only if the relevant policy or 5GC enforcement information does NOT require UP integrity. As the control inputs set SMF Integrity/Confidentiality Policy to N/A (not applicable), this does not trigger an automatic violation from missing enforcement, but the explicit disabling still presents a risk. As per 3GPP TS 38.300 and 33.501, integrity protection for user data is RECOMMENDED and provides defense for user plane data. Therefore, disabling it, even if policy does not strictly require it, is considered a non-compliant configuration for static secure configuration posture.

Violation Details
1. User Plane DRB integrity protection is explicitly disabled
High

Non-Compliant Value: no

Fix: Set drb_integrity = "yes"; to enable DRB integrity protection.

Reference: 3GPP TS 33.501 Clause 6.6.2, 3GPP TS 38.300 Clause 12.2

Specification Text:

Integrity protection for user data (DRBs) is recommended for user data integrity. Disabling it exposes user traffic to modification attacks. 3GPP TS 38.300 and TS 33.501 allow this to be per policy, but explicit disabling in static configuration is considered insecure posture.

Reflection Agent Analysis

The reported violation that the user plane DRB integrity protection is explicitly disabled by 'drb_integrity = "no";' is valid because this exact setting appears verbatim in the ORIGINAL_CONFIG. The corrected configuration correctly fixes the violation by changing 'drb_integrity' to "yes" without altering unrelated lines or adding new keys, thus meeting the minimal fix requirements. There are no additional insecure settings present in either ORIGINAL_CONFIG or corrected_config based on the provided evidence and parameters. Therefore, the corrected configuration can be approved as compliant.

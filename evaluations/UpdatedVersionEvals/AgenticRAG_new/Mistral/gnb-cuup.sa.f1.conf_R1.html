Security Compliance Report

File: gnb-cuup.sa.f1.conf
Function: gNB(CU-UP)
Status: Non-Compliant
Compliance Assessment Summary

The gNB(CU-UP) configuration file is non-compliant with 3GPP security requirements. Critical violations were identified for missing IPsec protection on the E1, F1, and SCTP interfaces. These interfaces must be confidentiality, integrity, and replay-protected using IPsec ESP and IKEv2 certificates-based authentication.

Violation Details
1. Missing IPsec Protection for E1 Interface
Critical

Non-Compliant Value: Not Configured

Fix: Add IPSEC_ENABLED = "true", IPSEC_POLICY = "ESP", and IKEV2_AUTH = "certificates" to the E1_INTERFACE configuration.

Reference: 3GPP TS 33.501 [3], Clause 5.3.10, 3GPP TS 33.501 [3], Clause 9.8.3

Specification Text:

The E1 interface between CU-CP and CU-UP shall be confidentiality, integrity, and replay-protected using IPsec ESP and IKEv2 certificates-based authentication.

2. Missing IPsec Protection for SCTP (F1-C Interface)
Critical

Non-Compliant Value: Not Configured

Fix: Add IPSEC_ENABLED = "true", IPSEC_POLICY = "ESP", and IKEV2_AUTH = "certificates" to the SCTP configuration.

Reference: 3GPP TS 33.501 [3], Clause 9.8.2, 3GPP TS 33.501 [3], Clause 5.3.9

Specification Text:

The F1-C interface shall support confidentiality, integrity, and replay protection using IPsec ESP and IKEv2 certificates-based authentication.

3. Missing IPsec Protection for F1 Interface
Critical

Non-Compliant Value: "f1"

Fix: Ensure IPsec protection is configured for the F1-U interface. This requires explicit configuration in the SCTP or F1 interface section.

Reference: 3GPP TS 33.501 [3], Clause 9.8.2

Specification Text:

The F1-U interface shall support confidentiality, integrity, and replay protection using IPsec ESP and IKEv2 certificates-based authentication.

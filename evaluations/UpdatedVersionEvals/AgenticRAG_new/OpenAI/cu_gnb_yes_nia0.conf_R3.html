Security Compliance Report

File: cu_gnb_yes_nia0.conf
Function: gNB(CU)
Status: Non-Compliant
Compliance Assessment Summary

The configuration is non-compliant with 3GPP security requirements because the integrity_algorithms list includes 'nia0' (null integrity algorithm) while the SMF Integrity Policy is set to 'Required'. 3GPP TS 33.523 and TS 33.501 require that a non-NULL integrity algorithm be used when integrity protection is required by policy. The presence of 'nia0' as a preferred integrity algorithm violates this requirement. No other violations were found for ciphering, DRB security, or SCTP configuration.

Violation Details
1. Null integrity algorithm (nia0) present when integrity is required
Critical

Non-Compliant Value: ( "nia0", "nia2", "nia1" )

Fix: Remove 'nia0' from the integrity_algorithms list.

Reference: 3GPP TS 33.523 clause 6.2.2.1.6, 3GPP TS 33.501 clause 5.3.3

Specification Text:

When SMF Integrity Policy is Required, only non-NULL integrity algorithms shall be used for user data protection between UE and gNB.

Reflection Agent Analysis
REVISION NEEDED: NO

The original configuration contained the null integrity algorithm 'nia0' in the integrity_algorithms list, which violates the SMF Integrity Policy requiring non-NULL integrity algorithms. The violation is supported by the provided KB evidence from 3GPP TS 33.523 clause 6.2.2.1.6. The corrected configuration properly removes 'nia0' from the integrity_algorithms list, leaving only non-NULL algorithms ('nia2', 'nia1'). No other changes were made, and no additional insecure settings are present in either the original or corrected configuration. Therefore, the corrected configuration is compliant and can be approved.

### **Compliance Assessment Phase**
#### **1. Ciphering Algorithms (`ciphering_algorithms`)**
- **Configuration**: `ciphering_algorithms = ( "nea0" );`
- **Violation**:
  - `nea0` is a **NULL ciphering algorithm**, which provides no encryption. This is **not compliant** with security requirements for user plane or control plane protection.
  - **Standard Reference**:
    - **TS 33.501 [3], clause 5.3.2**: Mandates the use of non-NULL ciphering algorithms for user data protection.
    - **TS 133 523 [5.2.2.1.4]**: Requires ciphering of user data based on the security policy sent by the SMF.
    - **Filename**: `TS 133 523 - V18.2.0 - 5G; 5G Security Assurance Specification (SCAS); Split gNB product classes (3GPP TS 33.523 version 18.2.0 Release 18).pdf`
  - **Security Risk**: Using `nea0` exposes user and control plane data to eavesdropping and tampering.
  - **Fix**: Remove `nea0` and replace it with **non-NULL algorithms** (e.g., `nea1`, `nea2`, or `nea3`).

#### **2. Integrity Algorithms (`integrity_algorithms`)**
- **Configuration**: `integrity_algorithms = ( "nia2", "nia0" );`
- **Violation**:
  - `nia0` is a **NULL integrity algorithm**, which provides no integrity protection. This is **not compliant** with security requirements for control plane or user plane protection.
  - **Standard Reference**:
    - **TS 33.501 [3], clauses 5.3.9, 5.3.10, 9.2, and 9.4**: Mandate integrity protection for control plane and user plane data.
    - **TS 133 523 [5.2.2.1.3]**: Requires control plane data integrity protection over N2/Xn/F1/E1 interfaces.
    - **Filename**: `TS 133 523 - V18.2.0 - 5G; 5G Security Assurance Specification (SCAS); Split gNB product classes (3GPP TS 33.523 version 18.2.0 Release 18).pdf`
  - **Security Risk**: Using `nia0` exposes control plane and user plane data to tampering and replay attacks.
  - **Fix**: Remove `nia0` and ensure only **non-NULL algorithms** (e.g., `nia1`, `nia2`, or `nia3`) are used.

#### **3. DRB Integrity (`drb_integrity`)**
- **Configuration**: `drb_integrity = "no";`
- **Violation**:
  - Disabling DRB integrity protection is **not compliant** with security requirements for user plane data.
  - **Standard Reference**:
    - **TS 33.501 [3], clause 5.3.2**: Mandates integrity protection for user plane data.
    - **TS 133 523 [6.2.2.1.7]**: Requires ciphering and integrity protection for user data between UE and gNB-CU-UP.
    - **Filename**: `ts_138401v160300p.pdf`
  - **Security Risk**: Disabling DRB integrity exposes user plane data to tampering and replay attacks.
  - **Fix**: Change `drb_integrity` to `"yes"`.

#### **4. SCTP Configuration (`SCTP_INSTREAMS` and `SCTP_OUTSTREAMS`)**
- **Configuration**:
  - `SCTP_INSTREAMS = 2;`
  - `SCTP_OUTSTREAMS = 2;`
- **Violation**:
  - While the configuration itself is not inherently insecure, **SCTP security requirements** mandate the use of **integrity, confidentiality, and replay protection** for control plane interfaces (F1-C, E1, NG).
  - **Standard Reference**:
    - **TS 33.501 [3], clauses 5.3.9, 5.3.10, 9.2, and 9.4**: Require confidentiality, integrity, and replay protection for F1-C, E1, and NG interfaces.
    - **TS 133 523 [5.2.2.1.3]**: Mandates control plane data integrity protection over F1/E1 interfaces.
    - **Filename**: `TS 133 523 - V18.2.0 - 5G; 5G Security Assurance Specification (SCAS); Split gNB product classes (3GPP TS 33.523 version 18.2.0 Release 18).pdf`
  - **Security Risk**: Lack of explicit SCTP security mechanisms (e.g., IPsec or DTLS) exposes control plane traffic to tampering and eavesdropping.
  - **Fix**: **No in-text fix possible** (requires IPsec/DTLS configuration, which is out of scope). However, this is noted as an **out-of-scope recommendation**.

#### **5. Logging Configuration**
- **Configuration**:
  - `f1ap_log_level = "info";`
  - `ngap_log_level = "debug";`
  - `sctp_log_level = "info";`
- **Violation**:
  - While `debug` and `info` log levels are not inherently insecure, **excessive logging** (e.g., `debug` for NGAP) can expose sensitive control plane information in logs.
  - **Standard Reference**:

    - **Filename**: `ts_138401v160300p.pdf`
  - **Security Risk**: Debug-level logs may expose sensitive control plane information (e.g., UE identities, keys, or signaling messages).
  - **Fix**: Change `ngap_log_level` from `"debug"` to `"info"`.

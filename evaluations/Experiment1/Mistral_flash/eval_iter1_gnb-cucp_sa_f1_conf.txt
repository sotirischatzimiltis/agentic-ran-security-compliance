### **Compliance Assessment Phase**
#### **Violations Found**
1. **Ciphering Algorithm Selection (`nea0`)**
   - **Violation**: The use of `nea0` (null ciphering) is explicitly prohibited for user plane and control plane protection in **3GPP TS 33.501 [3], clauses 5.3.2, 5.3.9, and 9.2**, and **O-RAN.WG11.TS.STS-R004-v11.00**.
     - **Standard Reference**:
       - *"The gNB shall not use `nea0` for ciphering of user or control plane data unless explicitly allowed by the SMF for specific use cases (e.g., emergency calls)."*
       - **Filename**: `ts_133501v180900p.pdf` (3GPP TS 33.501)
     - **Security Risk**: `nea0` provides no encryption, exposing user and control plane data to eavesdropping and tampering.

   - **Fix**: Remove `nea0` from the `ciphering_algorithms` list. The first algorithm in the list must be a secure algorithm (e.g., `nea1`, `nea2`, or `nea3`).

2. **Integrity Algorithm Selection (`nia0`)**
   - **Violation**: The use of `nia0` (null integrity protection) is explicitly prohibited for control plane and user plane protection in **3GPP TS 33.501 [3], clauses 5.3.3, 5.3.9, and 9.2**, and **O-RAN.WG11.TS.STS-R004-v11.00**.
     - **Standard Reference**:
       - *"The gNB shall not use `nia0` for integrity protection of control plane or user plane data unless explicitly allowed by the SMF for specific use cases (e.g., emergency calls)."*
       - **Filename**: `ts_133501v180900p.pdf` (3GPP TS 33.501)
     - **Security Risk**: `nia0` provides no integrity protection, exposing control and user plane data to tampering and replay attacks.

   - **Fix**: Remove `nia0` from the `integrity_algorithms` list. The first algorithm in the list must be a secure algorithm (e.g., `nia1`, `nia2`, or `nia3`).

3. **DRB Integrity Protection (`drb_integrity = "no"`)**
   - **Violation**: Disabling integrity protection for Data Radio Bearers (DRBs) violates **3GPP TS 33.501 [3], clause 5.3.2**, and **O-RAN.WG11.TS.STS-R004-v11.00**.
     - **Standard Reference**:
       - *"Integrity protection shall be enabled for all DRBs unless explicitly disabled by the SMF for specific use cases (e.g., emergency calls)."*
       - **Filename**: `ts_138300v170000p.pdf` (3GPP TS 38.300)
     - **Security Risk**: Disabling integrity protection exposes user plane data to tampering and replay attacks.

   - **Fix**: Set `drb_integrity = "yes"`.

4. **SCTP Configuration for F1-C Interface**
   - **Violation**: The SCTP configuration does not explicitly enforce **confidentiality, integrity, or replay protection** for the F1-C interface, violating **3GPP TS 33.501 [3], clauses 5.3.9 and 9.2**, and **O-RAN.WG11.TS.STS-R004-v11.00**.
     - **Standard Reference**:
       - *"The F1-C interface shall support confidentiality, integrity, and replay protection for all control plane traffic."*
       - **Filename**: `TS 133 523 - V18.2.0 - 5G; 5G Security Assurance Specification (SCAS); Split gNB product classes (3GPP TS 33.523 version 18.2.0 Release 18).pdf`
     - **Security Risk**: Lack of explicit SCTP security configuration exposes the F1-C interface to eavesdropping, tampering, and replay attacks.

   - **Fix**: While the configuration does not explicitly show SCTP security settings (e.g., IPsec or DTLS), the **existing fields cannot be modified** as they do not support security parameters. This is an **out-of-scope recommendation** for now.

     - **Standard Reference**:

       - **Filename**: `ts_133501v180900p.pdf` (3GPP TS 33.501)
     - **Security Risk**: Lack of explicit security configuration exposes the E1 interface to eavesdropping, tampering, and replay attacks.

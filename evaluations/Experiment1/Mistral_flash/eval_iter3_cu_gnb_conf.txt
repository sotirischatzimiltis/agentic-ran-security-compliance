#### **2. Compliance Assessment Phase**

##### **Violations Found**

##### **Violation 1: Use of Null Ciphering Algorithm (`nea0`)**
- **Field**: `ciphering_algorithms = ("nea0")`
- **Standard Reference**:
  - **3GPP TS 33.501, Clause 6.7.3.0** (Filename: `ts_133511v170100p.pdf`):
    > *"Each gNB shall be configured via network management with lists of algorithms which are allowed for usage. There shall be one list for integrity algorithms, and one for ciphering algorithms. These lists shall be ordered according to a priority decided by the operator."*
  - **3GPP TS 33.501, Clause 5.11.2** (Filename: `ts_133511v170100p.pdf`):
    > *"The serving network shall select the algorithms to use dependent on: the UE security capabilities of the UE, the configured allowed list of security capabilities of the currently serving network entity."*
- **Security Risk**:
  - `nea0` is a **null ciphering algorithm**, meaning **no encryption** is applied to user or control plane data. This violates **confidentiality requirements** for both the **F1 interface** and **NG interface**, as specified in **3GPP TS 33.501, Clauses 5.3.9, 9.2, and 9.4**.
  - Exposes **user plane data** and **control plane signaling** to eavesdropping, tampering, and replay attacks.
- **Fix Required**:
  - Remove `nea0` from the `ciphering_algorithms` list.
  - Replace with **strong encryption algorithms** such as `nea1`, `nea2`, or `nea3`.

##### **Violation 2: Use of Null Integrity Algorithm (`nia0`)**
- **Field**: `integrity_algorithms = ("nia2", "nia0")`
- **Standard Reference**:
  - **3GPP TS 33.501, Clause 6.7.3.0** (Filename: `ts_133511v170100p.pdf`):
    > *"Each gNB shall be configured via network management with lists of algorithms which are allowed for usage. There shall be one list for integrity algorithms, and one for ciphering algorithms."*
  - **3GPP TS 33.501, Clause 5.11.2** (Filename: `ts_133511v170100p.pdf`):
    > *"The serving network shall select the algorithms to use dependent on the UE security capabilities and the configured allowed list of security capabilities."*
- **Security Risk**:
  - `nia0` is a **null integrity algorithm**, meaning **no integrity protection** is applied to control plane or user plane data. This violates **integrity protection requirements** for the **F1 interface** and **NG interface**, as specified in **3GPP TS 33.501, Clauses 5.3.9, 5.3.10, 9.2, and 9.4**.
  - Exposes the system to **message tampering, replay attacks, and injection of malicious signaling**.
- **Fix Required**:
  - Remove `nia0` from the `integrity_algorithms` list.
  - Retain only **strong integrity algorithms** such as `nia1`, `nia2`, or `nia3`.

##### **Violation 3: Disabled DRB Integrity Protection (`drb_integrity = "no"`)**
- **Field**: `drb_integrity = "no"`
- **Standard Reference**:
  - **3GPP TS 38.300, Clause 9.2** (Filename: `ts_138300v170000p.pdf`):
    > *"Ciphering and integrity protection can be configured per DRB but all DRBs belonging to a PDU session for which the User Plane Security Enforcement information indicates that UP integrity protection is required (see TS 23.502 [22]), are configured with integrity protection."*
  - **3GPP TS 33.501, Clause 5.3.9** (Filename: `ts_133501v180900p.pdf`):
    > *"Integrity protection shall be applied to all DRBs where the UP integrity protection policy requires it."*
- **Security Risk**:
  - Disabling **DRB integrity protection** violates **3GPP requirements** for **user plane security**.
  - Exposes **user plane data** to **tampering, replay attacks, and injection of malicious payloads**.
- **Fix Required**:
  - Set `drb_integrity = "yes"` to enable integrity protection for DRBs.

  - **3GPP TS 33.523, Clause 5.2.2.1.3** (Filename: `TS 133 523 - V18.2.0 - 5G; 5G Security Assurance Specification (SCAS); Split gNB product classes (3GPP TS 33.523 version 18.2.0 Release 18).pdf`):

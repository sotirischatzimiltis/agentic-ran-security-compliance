Detection phase – Security-relevant fields and values:

2. integrity_algorithms = ( "nia2", "nia0" );

Standards lookup summary relevant to these fields:

- F1-C interface requires confidentiality, integrity, replay protection for control and user planes (TS 33.501 clauses 5.3.9, 9.2, 9.3, 9.4; TS 33.523; ts_138401v160300p.pdf; TS 33.523).
- SCTP must be secured on F1-C interface (TS 33.117, TS 33.523).
- Ciphering algorithms allowed: nea0, nea1, nea2, nea3. nea0 (NULL ciphering) is allowed but confidentiality protection should be used when permitted (TS 33.501).
- Integrity protection algorithms allowed: nia0, nia1, nia2, nia3. However, integrity protection shall not use nia0 for user data (TS 33.501).
- Data Radio Bearer (DRB) integrity protection must be enabled if required by the session (TS 23.502, ts_138300v170000p.pdf).
- Integrity protection of user plane adds overhead, but using nia0 for integrity provides no security benefit and is discouraged.
- Logging for security events is required (O-RAN WG11).

Violations found:

1. drb_integrity = "no"; violates requirement for integrity protection on DRBs if the policy requires it.
2. ciphering_algorithms = ("nea0"); only uses nea0 (NULL ciphering). Although allowed, confidentiality protection should be used if regulations permit.
3. integrity_algorithms includes nia0. Integrity protection shall not use nia0 on user data as it adds overhead without security benefits.
4. SCTP configuration does not show any explicit security enabling (e.g., no mention of SCTP authentication, IPsec, or TLS). However, lack of these is Out-of-Scope because missing features are not violations if not explicitly configured.

Fixes that can be done based strictly on the config to fix violations found:

- Change drb_integrity from "no" to "yes" to enable integrity protection on DRBs.
- Remove nia0 from integrity_algorithms because it should not be used for integrity protection.
- Change ciphering_algorithms from ("nea0") to at least one algorithm with real protection like "nea2" which is supported per the list. Since "nea0" is allowed but confidentiality should be used if the policy permits, changing to "nea2" is more secure.
- Keep other parameters unchanged.

Applying minimal changes only.

Security Impact Analysis:

- Enabling DRB integrity protection ("drb_integrity = yes") ensures the integrity and protection against tampering of user plane data on data radio bearers, preventing attacks that could manipulate user data.
- Removing "nia0" from integrity_algorithms prevents use of an insecure or non-beneficial integrity algorithm on user data, improving integrity security.
- Changing ciphering_algorithms from "nea0" (no cipher) to "nea2" strengthens confidentiality protection of user data and signaling, reducing risk of eavesdropping.
- Overall these changes bring the configuration into compliance with 3GPP and O-RAN security requirements for CU.
